# 需求内交互原型 · 第一版

入口：[打开交互原型](ai-talent-workspace-v1.html)。下载/复制这一个HTML即可在浏览器离线打开，无需启动服务。

本轮只做原型，没有修改frontend/src、后端、接口、数据库或本机5173应用。原型待李玉杰评审，不代表功能已按新界面实施。

## 建议试用
1. HR：简历筛选→筛选Python/3年以上→勾选两人→比较/问答→点来源→返回，检查条件与选择保留；也可翻到第2页打开人才后返回。
2. 岗位与匹配：选AI应用开发岗位→匹配结果（初始为v1旧结果）→发起新匹配→明确全外部范围→看满足/待核对/不满足→选择人才看解释→打开画像→返回原结果。
3. 岗位：编辑/JD辅助或新建需求。可载入合成JD查看建议；草稿允许缺失，确认生效前要补齐必要信息和确认条件一致。
4. 画像：事实/来源/测评/历史分区；技术/项目/证书分类；单人、选中、最近筛选、全部授权范围分开。可尝试学校、项目、比较和页面注明的预设条件人数问题。
5. 轻量测评：HR题库/发布/分配/任务/成绩；右上切员工可体验草稿、提交及客观规则评分。管理员视角只看系统管理，不提供人才正文入口。
6. 管理：账号绑定编辑、角色配置预览、新角色默认无授权、部门/公司岗位/部门岗位/人才库、菜单表预览和操作/AI记录。

## 原型边界
- 所有人物、学校、文件名、岗位、答案、分数、记录均为虚构合成演示。原型标识始终可见；没有连接真实API、模型或数据库。
- 问答只支持预设示例及有限关键词组合；评分/匹配交互不代表真实模型或匹配算法效果。匹配缺技能证据归“待核对”，明确学历/年限不足才归“不满足”，不以缺失冒充否定。
- 导入只读取文件名，不读取/上传文件正文；合成演示批次只是状态样例。来源是合成片段，不提供真实原文件下载。重复资料仅演示人工核验与待关联，不自动合并。
- 发布试卷保留当前题集快照；客观题按固定答案在浏览器内演示评分，不引入自适应出题、AI面试、软素质推断。
- 角色切换是固定场景预览，不是安全机制。角色/菜单表单只改配置预览，不动态实现正式后端鉴权。所有变更仅存当前页面内存，刷新即恢复初始样例。
- 不包含培训、独立智能问数、通用知识库、Agent编排管理、缺口/储备/邀约等延期能力。

## 与现有项目的关系
保留既有真实解析与人工保护、统一人才ID、JD同表单辅助、版本/快照、范围问答/证据、匹配及固定评分。原型重排六个工作区与两条核心动线。实施时需整理画像/匹配页面、列表摘要和事实来源入口，补工作台岗位及最近结果查询；原型的结构化学历/年限控件需要受控接口适配，不把现有原文包含当成数值语义筛选。

UI/UX Pro Max的state preservation检索已实际执行，采用活动导航、状态保留及范围隔离原则；本原型外观按本轮蓝紫参考与业务密度设计，不依赖外部字体或新UI框架。
