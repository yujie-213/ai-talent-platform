## 对照依据与失误
李玉杰本轮提供《AI数字化人才平台_交互原型修订_V1.0 (1).html》（标题R2）。已读取结构并用真实Edge打开，分别截图工作台、简历筛选与画像问答。原型作为视觉/交互参考；其中模拟数据、规则回答、演示角色切换和重置演示数据不构成正式系统功能指令，未搬进正式系统。

上一轮实际偏离：擅自采用蓝色体系和TALENT英文品牌；工作台以技术统计卡代替原型四格业务概览及业务入口；画像使用侧滑长抽屉，问答没有独立阅读区；导入入口下沉到页面底部。此前自动化通过只说明功能未断，不能证明设计符合预期。

## 本轮改动
- 使用原型“人才·有数”品牌、深青导航、青绿色主色#087f79、浅灰绿内容底色#f4f7f7及克制的边框/阴影，白色通栏顶部；统一主题作用于岗位、测评、管理、登录等既有页面。
- 工作台恢复原型业务引导区→四格概览→“从这里开始”与进展双栏→统计明细。全部数字仍来自现有workbench接口；没有把其不提供的“有效岗位数/待核对人数”伪造成数字，改为已授权人才、处理中任务、待参与测评、本人历史已评估匹配明细。原型的模拟近期日志替换为真实统计明细，不造近期业务记录。
- 简历工作区恢复候选人/导入解析两个页签；顶端“上传简历”直接进入真实导入区，筛选面板有分区标题。人才保留前轮已明确选择的卡片，不退回旧原型表格；未新增无后端支持的姓名/年限/匹配分筛选或疑似重复总数。
- 人才画像改为原型的居中1160宽弹窗，顶部/底部固定、左侧档案独立滚动、右侧问答独立滚动；窄屏上下布局。文件、测评、修改历史仍可到达，字段来源默认折叠，正常事实用细线履历块。
- 问答改为原型的范围说明、问题示例、空态、问题气泡、答案/来源、底部输入与全宽发送。技术任务编号/执行版本收到“进度与执行详情”，没有删除恢复和失败操作；示例仅填问题，实际发送仍走原API/Worker。来源弹窗append-to-body，防止被画像独立滚动区域裁切。
- 保留原动作权限/菜单key及导航名称，既有岗位表单内JD/匹配能力不为视觉对齐拆成没有业务支撑的新模块；本轮没有改后端或数据库。

## 发送按钮被裁切修复（2026-11-06）

李玉杰截图指出画像问答发送按钮无法点击，这是实际布局缺陷，前轮“可见”断言不足以排除祖先裁切。已在1272×596逻辑视口、1.5设备比例（1908×894截图，与用户截图等效）先复现：旧代码发送按钮viewport ratio=0，测试明确失败。

根因：侧栏固定高度与overflow:hidden叠加，范围说明/示例不收缩，聊天记录又有100px最小高度，短视口下整体超高，输入区与发送按钮被裁在面板外。修复ChatWorkspace：两行grid（可收缩滚动阅读区＋自然高度输入区）；范围、示例、答案统一在上方阅读区滚动，取消聊天记录的100px最小高度；输入框禁止拖拽撑高；短视口输入框54px但内部可滚动编辑。没有改变会话/API/任务、授权和幂等。

新增chat-composer-layout.mjs为明确合成API回归，检查按钮100%在视口、完整处于所有滚动/裁切祖先内、真实鼠标命中；初始与300段长回答后均检查，并实际连续发送两次。尺寸：用户150%等效1272×596、1366×768、1440×900、1100×500、800×650；窄屏上下布局先正常滚动到AI区，再检查内部无裁切。不是只断言display可见，不force点击。五种尺寸均通过。截图只含合成数据，data/ui-composer-fix/user-150-percent.png已实际打开自查，发送按钮完整显示。

chat-composer-live.mjs另用真实API/Worker/模型及已有合成审查档案，在相同150%等效显示下鼠标发送“毕业院校是什么？”，检查202、具体学校回答及回答后按钮100%在视口和可点击。最终结果随收尾记录，不用合成响应冒充真实模型。

修复最终验证：五尺寸合成可点击性回归重跑通过；真实150%等效显示下消息POST202、学校具体答案返回、按钮完整在视口及trial鼠标命中通过。npm run build类型与生产构建通过（既有包体警告保留）。代码HEAD 7a02775；本机5173热更新生效，未改后台服务。最终文档HEAD用git log查看，正常推送同名UI分支。
