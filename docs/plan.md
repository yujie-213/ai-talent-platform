## 阶段一：可运行的权限与人才底座（已验收）
目标：登录后按权限手工建档、查看和维护人才，文件与后台任务基础可验证。

### 任务
1. 本机环境检查和隔离方案；Git 初始化/复用、GitHub 仓库关联、.gitignore（本次用户明确要求公开，覆盖默认私有）。
2. 前后端工程骨架、统一配置/响应/错误/日志、锁定依赖、README、.env.example。
3. docs/schema.md 和 docs/api.md 的阶段一详细设计、Alembic 首批迁移、合成测试数据。
4. 账号登录/启停与最小角色授权能力，当前有效权限，用户与人才绑定。
5. 内部部门、公司岗位/部门岗位、外部负责人/人才库授权数据基础。最小维护入口满足本阶段建档与权限验证。
6. 人才人工建档、列表/详情/编辑、来源标记、当前版本及修改历史；有效事实与后续文件抽取的数据契约预留必要字段。
7. 文件上传/校验/受控存储/下载、逐文件任务记录；不做假 OCR 或假结构化抽取。
8. Celery/Redis、task/attempt/outbox、投递补偿、任务恢复、失败及重试、进度查询。
9. 前端最小可用页面与关键审计。必要基础权限配置可用种子/受控脚本验证；完整管理页面后续补齐，不能以此宣称 V1 管理模块完成。
10. 验证、文档、提交/推送和交接。

### 验收
- S1-01 按 README 可启动；空项目数据库通过迁移建立，合成数据可载入；已有服务不受破坏。
- S1-02 HR 可手工建立外部人才，外部人才无内部部门；授权内查看修改及完整联系方式可用。
- S1-03 员工仅本人获授权档案，更换 Talent ID/文件 ID/任务 ID 越权拒绝。
- S1-04 系统管理员无业务授权时不能直接读取人才正文/文件/联系方式。
- S1-05 禁用账号或撤销权限后，旧 JWT 的后续请求被拒绝。
- S1-06 同账号可全公司看、本部门改，验证范围不会被跨动作借用。
- S1-07 两人同版本编辑，后提交冲突，无静默覆盖。
- S1-08 文件校验/上传/下载受控，路径越界和绕过直接访问被拒绝。
- S1-09 幂等键重复返回同一业务记录；同键不同内容冲突；不同账号不会串结果。
- S1-10 用明确标识的测试任务验证执行、失败、重试；投递失败可补发、重复消息不重复成果、Worker 重启任务可恢复/明确失败、旧执行不能覆盖新执行。
- S1-11 审计可追踪关键动作，技术/授权/业务结果不混淆，敏感内容未裸记。
- S1-12 进度/交接/架构路径真实准确；测试命令/结果/替身与未验证项明确；仓库远端可用时已推送。
- S1-13 部门岗位基础能区分不同部门同名岗位，为后续需求绑定提供真实数据基础。
验收资料包括启动步骤、合成账号说明、实际测试记录、页面核验步骤和已知限制。不能只凭静态检查宣布以上集成场景通过。
