# 技术设计基线 V0.1

日期：2026-11-05；状态：架构和业务规则已讨论确认，详细表/接口/依赖版本尚待实现前补齐。
权威产品输入：冻结 PRD + docs/decisions.md。本文不宣称已经实现。

## 1. 架构和环境
- 模块化单体、前后端分离。Vue 3/TypeScript/Element Plus；FastAPI；SQLAlchemy/Alembic/MySQL。
- 同一后端项目分别运行 HTTP API 与 Celery Worker；Redis 作为 Broker；MySQL 保存权威任务和成果，不依赖 Redis 临时状态保存全部业务历史。
- LangGraph 处理确有必要的条件分支与有状态 AI 流程，普通 CRUD/测评评分不用 Agent。
- Milvus 保存可重建检索索引；本地 Ollama bge-m3 Embedding；本地 PaddleOCR；生成模型 API。
- Windows 学习电脑，Docker Desktop Linux 容器；Conda 本机开发后端，前端本机 Node。Worker/OCR 容器共享后端代码。
- 原文件受保护目录，API/Worker 共享挂载、使用文件 ID/相对路径，不在数据库传递 Windows 盘符路径。路径规范化，拒绝越界，校验文件真实类型与可读取性。
- Compose 服务端口、库名、卷隔离；尊重已存在的 MySQL/Milvus/Ollama。确认兼容性后复用或用隔离项目，不破坏用户现有学习环境。
- 主机和容器的 MySQL/Redis/Ollama 地址可能不同，由环境配置区分；不把容器中的 localhost 误当 Windows 主机。
- bge-m3 预期 1024 维，实际调用验证并锁定模型/维度。限制批次与并发；不消耗云端 Embedding 额度。
- 不预设机器有可用 GPU，不预先承诺吞吐和时延。

## 2. 核心模型
### 身份和授权
User、Talent 分离，可选一对一绑定。内部员工有部门和可选部门岗位；外部候选人无本企业部门，管理 HR/人才库授权、职业标签及应聘关系分开。
User-Role 多对多；权限对应动作，数据范围与动作授权绑定，不能用查看的全公司范围放大修改权限。角色默认授权联系方式，HR 不另走申请。
本人/指定部门/全公司内部范围与外部负责 HR/人才库授权分别判断。多角色合并只合并同项动作的有效授予，未授权默认拒绝。

### 人才、来源和版本
Talent 保存当前档案及版本；教育/经历/项目/技能/证书以适合查询的结构管理，不把所有内容塞入不可查询的大 JSON。
File/ImportBatch/ParseTask/Extraction 保存原文、逐文件处理、来源及页码/段落定位。
关键事实带来源类型、来源版本、确认状态、时间；人工修改保留历史。文件抽取事实、AI 推断、测评结果分开。
初次正常解析可入档；异常字段标核对，不强制所有结果都人工确认。后续人工确认值不自动覆盖。
未确认空字段校验后可补充；冲突供核对；列表信息避免重复添加。身份不确定不覆盖已有档案。
文件内容哈希不作为人才身份或跨用户信息披露依据。疑似重复功能按授权展示对比，无通用自动合并引擎。

### 公司岗位和招聘需求
PositionDefinition -> DepartmentPosition -> RecruitmentRequirement。
同名岗位可属于不同部门；需求有草稿、当前有效版本和停用状态。
有效版本不可变；未确认草稿不改写当前有效版；停用拒绝新匹配，已有任务按快照运行并标当前状态。
姓名/部门/地点/薪资/职责/明确要求是有效需求必填；不限项显式；薪资币种周期区间校验，“面议”枚举待表单设计确定。
AI 不编造企业事实；粘贴 JD 提取与完善返回建议/差异，不能无提示覆盖人工修改。
部门缺口看板/编制管理延期，不创建未来占位模块。

### 任务、快照和会话
业务 Task 与 ExecutionAttempt 分开；attempt/run version 检查迟到写入。批次汇总能逐文件对账。
MatchTask 绑定需求有效版本、实际人才范围、资料快照、规则及相关模型配置；结果包含分数、条件判断、证据、缺口和解释状态。
Conversation/Message 保存用户、范围、条件、时间和引用。新请求重新鉴权并查询当前资料；旧回答保留版本和时间，不当最新事实。
Checkpointer 只保存流程状态，不能替代业务表。具体持久化适配器在进入 AI 阶段前验证和决定；不能把内存 Saver 当重启可恢复，也不假设 MySQL 天然兼容官方适配器。如需新增数据库或社区依赖，说明影响后确认。

## 3. 简历解析
文件校验 -> 按页文字提取/OCR -> 结构化抽取 -> 程序校验 -> 新建/确认关联 -> 索引更新。
文本页直接提取，扫描页/图片走 PaddleOCR，混合 PDF 按页处理。DOCX 覆盖段落、表格与内嵌图片的实际读取/OCR路径。
抽取结果保留可定位依据；缺失不编造；OCR 与抽取分别评测。PDF/DOCX 具体库及依赖版本通过样本验证后锁定。
状态待处理/处理中/成功/需核对/失败；技术执行与字段可用程度分开记录。
指定档案上传明确关联但身份线索冲突须拦截更新；普通上传重复手机号/邮箱提示 HR 对比，不能仅姓名或向量相似自动合并。
限额需配置并在上传页显示，至少文件大小、页数、批次数，损坏/加密/不支持明确反馈。
PaddleOCR CPU 为起点，不承诺复杂版式准确；版面顺序问题按样本决定补强，不能静默成功。

## 4. 匹配
默认全部授权外部候选人，可包含内部员工并排除目标部门现任员工；名单与版本在启动绑定，不因运行期间新增人才改变范围。
结构化必备条件由代码判断满足/不满足/未知；没写不等于没有。技能声明和项目使用均算证据，熟练度留面试。
对范围内全部对象处理，不用全局向量 top-k 作为人才全集；可按人检索片段以控制上下文。
语义模型提供相关性信号，程序按有版本的规则汇总，模型依据结果解释。向量相似度不是最终匹配分，分数不是录用概率。
以排名列表为主，硬条件与未知清楚标注和可筛选，明确不满足不能无说明混入合格排名。
权重/阈值通过标注样本形成基线，不预设最佳数值；正式样本前可有明确标注的初始配置。
解释失败保留已完成判断/分数，解释状态单独记录。旧结果不覆盖，源数据变化标需更新。
运行中访问及结果读取检查当前授权，快照不成为撤权绕过渠道。
不自动录用，不实施内部调岗，不自动建立应聘关系。

## 5. 统一档案聊天
意图/范围识别 -> 受控计划校验 -> 结构化查询/证据检索/组合或全范围评估 -> 引用校验 -> 回答。
模型输出允许字段/操作符/值/排序的受约束结构，不直接执行任意生成 SQL。后端注入身份范围、分页和资源限制。
详情起始当前人；勾选起始选中人；筛选起始完整筛选条件、不局限当前页；独立入口默认全部授权人才并明确显示。
范围变化明确提示，用户明确要求可切换，不明确先澄清；空选/无结果不自动扩大。追问沿用明确范围。
结构化查询/人数完整过滤，按 Talent ID 去重；本科与本科及以上、以上与超过等歧义不能暗改。
语义找人可报告当前找到结果；语义总数须先明确标准，后台逐人评估并报告已评估/符合/不符合/未知、失败及截断，不宣称客观绝对人数。
引用关联人才、来源文件/记录、页码/片段及版本；多人证据不串人。结构化统计显示条件/范围/时间/明细，不伪造文档引用。
授权资料在进入模型前按字段权限处理，取回后再次检查权限和版本；员工不能经摘要/引用/文件推断他人资料。
有效人工事实与旧原文冲突时说明，不盲信旧证据。只读，不经聊天修改资料或做录用决策。
模型失败时可展示已成功的实际查询结果并说明整理失败；保留问题、范围，重试不重复业务。

## 6. 检索与索引
按语义段落/项目/经历切片，保留来源和版本；过长片段再分段。稠密 + BM25 + RRF；重排是否启用按效果/耗时比较。
业务权限限制应进入检索过滤；结果还要验证当前有效范围/版本。不能仅前端过滤。
MySQL 是权威源；索引事件可补偿重放。更新、删除、授权调整都需处理；过期证据丢弃、索引未就绪明确提示。
模型/维度变化创建新索引重建，不混用不同空间。
文档和索引中真实敏感资料按策略清理，历史快照不意味着无限保留。

## 7. 测评
单选/多选/判断，固定题库、试卷发布快照。分配给已绑定人才账号的员工，授权 HR 管理；外部无账号在线测评延期。
多选完全正确得分；未答零分并提交前提醒；保存答题草稿。
任务状态：待作答/作答中/已提交待评分/已完成/已取消。仅未提交任务可授权取消。
提交归属/题目/状态/答案校验，重复返回原结果；答案锁定后评分失败只重试评分。
同员工同试卷可显式分配新任务，网络重试不得多分配。
保留总分/维度/满分/版本/时间/答题。员工看本人结果，不返回标准答案；HR 在范围内查看。
不从简历推算雷达分，不把跨试卷百分制默认当可比较，首版不把成绩混入匹配分。

## 8. API、一致性与日志
正常 HTTP 状态 + 稳定业务错误码 + request_id/trace_id；异步接受返回 task_id/查询入口，不预报成功。
幂等键按账号与动作限定，保存请求摘要和结果引用；同键不同内容冲突。业务约束仍需独立存在。
乐观锁检测档案/需求编辑冲突，原子写入时检测版本而非先查后无条件覆盖。
任务记录与 outbox 同事务；投递可重复，消费需幂等。使用领取/心跳或租约/执行版本及恢复策略，具体实现写入设计。
重启时恢复或明确失败/可重试；不长期卡处理中；重试不无界叠加，毒性文件和格式错误区别临时网络问题。
短事务、唯一最终成果、迟到 attempt 拒绝、已保存成果查询后决定重试。
任务页面先用轮询，完成/失败停止；聊天 SSE/流式，断开不自动创建新业务。
记录请求、任务、执行、模型调用追踪。技术成功、授权拒绝、业务是否完成分开。普通日志不记敏感正文/令牌。
统计遵循同一授权并与主库对账，不使用硬编码经营数据。
