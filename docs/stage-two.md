2026-11-05；授权基线 main 7dbdb86（含 d2f3dbd 验收记录）。第一阶段已验收；第二阶段待用户验收，不进入第三阶段。

## 实施顺序
1. S2-01 环境核实、真实格式读取与 CPU OCR 样本；逐页/段落证据、资源上限。
2. S2-02 受约束模型抽取与程序验证；原文、结果、异常分开保存。
3. S2-03 迁移、普通导入/指定关联、批次逐文件对账、执行版本及人工编辑保护。
4. S2-04 授权内重复核对、更新建议、分类标签和组合筛选。
5. S2-05 MySQL 同事务索引事件、切片版本、Ollama/Milvus 更新及补偿。
6. S2-06 页面拆分、真实页面闭环、故障/权限/第一阶段回归、文档与交付。

## 契约和边界
- 原文件 10 MiB；PDF 50 页；批次最多20份；图片2500万像素；DOCX 解压50 MiB/1000条目。超限明确拒绝，上传页面显示相同限制。
- PDF 每页取字，低文本页渲染 OCR；含实质图片的文本页也识别图片，避免混合页漏失。DOCX 按正文 XML 顺序读取段落、表格单元格和关系引用内嵌图片；不访问外链。
- 阅读器只产生 locator/text/method 证据。OCR、模型抽取、Embedding 和 Milvus 分别独立入口，不持有数据库会话。外部调用设超时，异常不携带原文或供应商响应到日志。
- 模型只返回允许字段及证据编号；程序检查引用原文、字段长度/枚举、联系方式、时间先后。缺失值用空值，不能靠模型补齐。
- 技术任务 succeeded 与资料 complete/needs_review、索引 pending/ready/failed 分开。模型配置缺失是明确失败，不能回退固定结果。
- 人工编辑通过 Talent.version 条件更新；抽取保存前再检权限与源版本。人工确认内容保留；空未确认字段可补充；冲突保存建议；列表规范化去重。明确关联的身份冲突阻止自动更新。
- 普通导入仅在当前查看授权内按手机号/邮箱提示对比，不自动合并。任务及原文读取重新鉴权，批次不泄露授权外结果。
- MySQL 保存有效切片、来源/档案/抽取/模型版本及待索引事件；外部索引写入可幂等重放。读取验证当前授权及有效版本；旧向量不能作为当前事实。
- 本阶段无岗位匹配、档案聊天或新持久化基础设施；岗位分数入口须显示未实现，不生成分数。
