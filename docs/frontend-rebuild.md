## 已实现的工作区

| 工作区 | 实际行为与关键入口 |
|---|---|
| 工作台 | 删除占首屏的宣传区。真实授权人才、岗位状态、处理中解析和测评；待办可进入对应工作区，当前岗位与本人最近匹配可直达岗位或具体批次。员工呈现本人档案与测评，管理员呈现获授权管理入口。`Workbench.vue` / `services/workbench.py` |
| 简历筛选 | `CandidateTable.vue` 一人一行，多列展示教育/经历、技能、项目、应聘岗位、分组、已有分数与生成时间。项目可展开，技能全部可见；不以索引状态充当人才质量。保留真实20条分页、本页选择和完整筛选快照；未提交输入不会串入聊天。导入和逐文件状态另一个页签，批次使用可辨识序号而非只显示完整 UUID。 |
| 人才画像 | 人才列表复用筛选、比较和范围问答，档案以独立工作页面阅读，返回保留原列表或岗位结果。`ProfileWorkspace.vue` 把事实/来源文件/测评/修改历史分区，事实有就近来源按钮；打开来源重新读取当前授权资料。AI 按需收起，收起保留会话；窄屏默认先读资料，显式打开 AI 后聚焦问答，仍可返回资料。 |
| 岗位与匹配 | 岗位列表进入工作页面，明显分为概览、匹配结果、版本历史、编辑/JD。概览使用当前有效快照，草稿编辑不改变生效条件。默认打开最近结果，名单与选中人才解释就近呈现；高亮与解释使用同一选择状态。新匹配只有明确的发起入口，确认范围和参数后开始；默认外部全范围、可选内部及排除目标部门的规则保留。 |
| 轻量测评 | 默认任务与成绩；管理者按题库、试卷、分配操作，员工以本人任务为中心。档案内只嵌入测评记录与结果，不再塞入完整测评管理页面。草稿、锁定提交、规则评分与历史保留。 |
| 系统管理 | 一级管理域内分账号、角色/菜单、基础资料和审计。账号列表先浏览，再打开独立编辑表单，保存仍携带版本。`AccountWorkspace.vue`、`CatalogWorkspace.vue` 拆离 App；角色列表选择后编辑当前角色，避免整页堆叠所有角色。保留当前功能/数据范围交集和实时后端鉴权；新增停用岗位、账号、基础资料的明确确认。 |

普通业务不再显示“测试成功/失败”、重建索引等工程按钮。测试接口和任务恢复机制没有删除，真实机制测试由开发脚本调用。问答入口不要求选择 SQL/RAG 技术模式；本轮进度、覆盖和失败状态保持可见，详细执行编号归入诊断。历史问题与历史回答分开显示。

## 必要的展示与筛选薄适配

- `/workbench` 新增当前岗位状态、最近岗位、本人最近匹配的最小展示信息；岗位复用原部门范围，匹配人数复用现有读取时鉴权。解析统计只计 `resume_parse`，不把机制测试混为解析业务量。
- `/talents/{id}` 可读事实补充当前可读原文件的任务、位置和原文依据。`repositories/fact_sources.py` 同时供画像和匹配复用；另校验文件读权、Task/File 当前归属，人工事实不伪造文件。
- 筛选新增 `minimum_education` 和 `minimum_experience_years`，原来的教育/经历原文包含控件保留且明确命名。复用既有匹配规则 v3，已完成学历、总年限和技能年限不混淆；未知、不足、在读等不冒充满足。列表与聊天使用 `candidate_filters` 同一实现，七个条件可完整传入固定范围。无新匹配算法或分数规则。
- 未新增迁移、模型服务或依赖，没有重置、清理或升级数据库、容器卷、Milvus/Ollama。API 与本项目 Worker/dispatcher/indexer已正常重载；前端继续使用原5173开发服务。

## 业务验收顺序

1. 打开 `http://127.0.0.1:5173`，使用本机既有账号（仅在忽略的 `data/local-access.txt`）。无需重新初始化、seed 或迁移。
2. 简历筛选：按技能、最低学历/年限及岗位组合筛选→勾选比较/按范围问答→核对来源→打开画像→返回，核对输入、分页与选择没有丢失。
3. 人才画像：阅读事实与项目→核对来源→来源文件下载/解析→测评记录/历史→展开AI并连续追问；短窗口、放大显示时实际点击发送。
4. 岗位与匹配：进入岗位→核对有效概览→匹配结果/历史→发起新匹配并确认范围→按三态分组看人和解释→画像→返回原批次。编辑/JD保存草稿后仍须核对确认生效。
5. 测评：HR在题库/试卷/分配完成操作，员工在本人任务答题、存草稿、提交和看成绩。管理员在管理域核对账号/角色/组织/菜单/审计，不默认进入人才正文。

## 限制与交接

- 本轮未重跑整个后端SQLite/MySQL全套、断Redis/强杀Worker故障测试或负载测试；上述恢复机制沿用原实现，本轮做了任务分页及真实正常Worker执行验证。
- 真实AI验证仍是小规模合成资料，不证明总体准确率、复杂版式或大规模人才查询性能。数值筛选先在授权内读取事实再按代码规则筛选，尚无大规模基准。
- 表格在窄屏采用局部水平滚动，完整履历仍可打开画像阅读；窄屏资料与AI聚焦切换，不常驻三列。桌面并列阅读和来源/测评等必要信息均保留。
- 所有本轮真实写入均为清楚命名的合成档案、文件、题目、试卷、岗位或测试角色/账号；没有删除用户数据。管理测试新账号最终禁用解绑，合成业务记录保留用于复核。
- 原 `ui-redesign-live`、`ui-prototype-*` 和旧 composer 专项脚本属于前次卡片/弹窗布局的历史验证入口；本轮布局以新增 `test:frontend-rebuild` / `test:frontend-rebuild-live` 和本页命令为准。已同步当前常用业务回归脚本；旧规则提示专项依赖真正的旧规则样本，未将新v3结果伪称旧规则。
- 不合并main，不进入第五阶段，不发布公网。提交及远端状态见当前 `handoff.md` 和 Git，状态最终仍为待用户验收。
